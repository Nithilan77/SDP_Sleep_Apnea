## 0. The 60-second version

- We are building a **wearable screening tool for sleep apnea** (breathing pauses during sleep). One chest sensor (ST SensorTile.box PRO) records **ECG** (heart signal, through its QVAR channel) and **chest motion** (its accelerometer = a proxy for breathing effort).
- It is a **screening** idea, not a diagnosis. Nothing here is clinically validated.
- We can't train on sleep-apnea patients from our own team (our volunteers are healthy 19–20-year-olds), so the **clinical labels come from public datasets**: PhysioNet Apnea-ECG and MESA.
- Our own recordings are used for a **different, smaller task**: detecting **voluntary breath-holds** (a safe imitation of "breathing stops"). A breath-hold is **not** an apnea event, and we never label it as one.
- **Main results:** (1) the best ECG-only model is **gradient boosting on heart-rate-variability features** (accuracy 0.802, AUROC 0.839); (2) **ensembles, augmentation and simulated data did not improve on it**; (3) the breath-hold detector works partly (finds 4 of 7 holds) but gives false alarms; it is one volunteer's data; (4) the dashboard now works end to end.
- **The honest headline:** the pipeline works; most of the "more data / more models" ideas turned out **not** to help; the real bottleneck is **more independent labelled data**.

## 1. Background you need (plain-language glossary)

| Term | Meaning |
|---|---|
| **Sleep apnea** | Repeated breathing stops/reductions during sleep. **AHI** = events per hour (<5 normal, 5–15 mild, 15–30 moderate, >30 severe). |
| **PSG** | Polysomnography: the overnight lab study that is the gold standard. Expensive; the reason a cheap screen is useful. |
| **ECG / R-peak / RR interval** | ECG = heart's electrical signal. R-peak = the spike of each heartbeat. RR interval = time between two beats (seconds). |
| **CVHR** | Cyclic Variation of Heart Rate: during apnea the heart slows, then speeds up when breathing resumes. The "heart fingerprint" of apnea. |
| **HRV features** | Statistics of beat-to-beat timing (variability, swing, etc.). |
| **QVAR** | The SensorTile's electrode channel. We wire it as ECG. Our files sample at about 243 Hz (nominal 240). |
| **IMU / accelerometer** | Motion sensor in the same box. On the chest it picks up breathing movement. |
| **Obstructive vs central apnea** | Obstructive: airway blocked, effort continues. Central: effort stops. Only a breathing-effort signal can tell them apart. |
| **Epoch / window** | A chunk of signal analysed at once. PhysioNet labels are **per minute**. |
| **AUROC** | How well a model ranks positives above negatives (0.5 = coin flip, 1.0 = perfect). Threshold-free. |
| **Sensitivity / specificity** | Fraction of real events caught / fraction of non-events correctly left alone. |
| **LOSO** | Leave-one-subject-out: train on all people but one, test on the one left out, repeat. The honest way to test on "new people". |
| **Seed** | Random starting point of training. We average over 3 seeds to see how much results wobble. |
| **Confidence interval (CI)** | Range the true difference plausibly lies in. If a CI for "model A minus model B" contains 0, we can't claim A is better. |
| **Data leakage** | Information from the test person sneaking into training. Makes results look better than they are. |
| **Augmentation** | Making altered copies of real data (scaling, noise, small shifts) to train on. |
| **Synthetic data / simulator** | Data generated by a program, not recorded from people. |
| **Ensemble** | Combining several models' outputs (averaging, voting, stacking). |
| **SSL** | Self-supervised learning: pre-training a model on unlabelled signals. |
| **Track A / Track B** | Our new naming: **A** = public datasets (PhysioNet, MESA). **B** = our own breath-hold recordings. They are never mixed. (Old docs called MESA "Track B"; ignore that.) |

## 2. What the system is meant to be

Two branches that are combined at the decision level (so we can always explain *why* something was flagged):
- **ECG branch:** ECG → R-peaks → RR intervals/CVHR features → model → probability of apnea per minute. Trained on PhysioNet.
- **Effort branch:** accelerometer → breathing-band filter (0.08–0.6 Hz) → effort amplitude → "did breathing stop?". There is no public dataset with this sensor, so it is signal processing plus a few small learned heads.
- **Claim to prove:** fusing both beats either alone. On MESA (belts instead of an accelerometer) it does: AUROC 0.780 vs 0.609 ECG-only.

## 4. The rule change (important to explain)

**Before:** "Our recordings are validation-only. Never train on them."
**Now (CLAUDE.md §4, 2026-10-20):** we **may** train, fine-tune, augment, use SSL, generate synthetic data and calibrate with our recordings — but with four guard-rails:
1. **Labels keep their meaning.** Breath-holds are `voluntary_breath_hold` (plus `baseline_reference`, `recovery`, `uncertain`). They are never relabelled as sleep apnea. A breath-hold model is a breath-hold model.
2. **Separation.** Anything used for training, model selection, calibration or generator fitting cannot be presented as an independent test for that experiment. With two volunteers, in-house results are "feasibility / training demonstrations".
3. **Two tracks never merged.** No in-house or synthetic data enters the public test folds.
4. **Privacy unchanged.** Raw recordings are never committed.

The old wording was removed from docs, code comments and dashboard text. A unit test fails if it reappears. We found **no code** that enforced the old rule — it lived only in text.

**Say it like this:** "We now allow training on our own data, but we keep voluntary breath-holds separate from clinical apnea and keep public and in-house results in separate tracks."

## 5. Track A: the public-data results (baseline you compare against)

All **per-minute, leave-one-record-out (35 folds)**, 3 seeds, threshold 0.5. (`results/expA_multiseed/`, `results/phase2_cvhr_baseline/`, `results/phase3_cnn/`)

| Model | Accuracy | AUROC | Note |
|---|---|---|---|
| Classical CVHR + logistic regression (Phase 2 floor) | 0.711 | — | 7 hand-made features |
| 1D-CNN, **historical headline** | 0.812 | — | One saved run; the CNN variant was chosen on the same test folds; the 3-seed average of that recipe is 0.778 ± 0.030. **Don't headline 0.812.** |
| **Gradient boosting (HGB) on HRV/CVHR features** | **0.802** | **0.839** | Best under one clean protocol |
| TCN | 0.760 | 0.797 | |
| CNN (clean protocol) | 0.753 | 0.807 | |
| Logistic regression | 0.737 | 0.783 | |
| GRU | 0.717 | 0.739 | |
| LSTM | 0.692 | 0.710 | |

**Clean protocol** (so the numbers are fair): 5 training records are held out as validation; early stopping and the decision threshold are chosen on those only; the test record is touched once.
**Verified this session** by recomputing 0.7111 and 0.8116 from the saved prediction files.
**Interpretation:** HGB and CNN are statistically tied (the CI for their difference includes 0); GRU/LSTM are worse; the literature target (87.9%) is not reached by our setup. We compare with 0.812 only as "historical".

**MESA (subject-grouped 5-fold, 220 subjects)** (`results/mesa/canet/`): ECG-only 0.609; effort-belt only 0.747; **ECG + effort (CANet, cross-attention) 0.780**; adding SpO2 0.813; SpO2 only 0.775. Our wearable has **no SpO2**, so the practical number is 0.780.

**Say it like this:** "Under one consistent protocol the best ECG-only model is gradient boosting on heart-rate-variability features, 80% per-minute accuracy; fusing breathing effort helps a lot on MESA (0.78 vs 0.61 AUROC)."

## 6. Earlier in-house findings (before today, for context)

- **Effort drops during breath-holds on real hardware.** Session 1: effort ratio (hold vs the 15 s before) was below 0.8 in 7 of 7 holds with a conservative window. Boundaries could not be detected automatically in a reliable way.
- **The belt-trained model doesn't transfer to the accelerometer.** The MESA-trained CANet flagged 94% of healthy-volunteer time; a classifier could separate belt from accelerometer signals almost perfectly (AUROC 0.997). Four domain-adaptation attempts did not fix it. Reason: belt and accelerometer signals are different physical measurements.
- **The ECG amplitude channel doesn't transfer** (QVAR amplitude is about 100× off PhysioNet scale).

### 7.2 The `headline.pt` dashboard error — root cause and fix
- **Cause:** the code loaded the model from a path *relative to the working directory*, and `data/mesa/` is gitignored, so a fresh clone (or one made before the commit that force-added the file) has no such file → `FileNotFoundError`.
- **Fix:** `src/deploy/checkpoints.py` resolves paths from the project root, checks a SHA-256 hash listed in `docs/checkpoints.json`, and raises a clear error telling you what is wrong and how to fix it. **It never substitutes another model.** `python -m src.deploy.checkpoints` shows the status of all model files; the dashboard has a **System status** page.

### 7.3 Policy change — section 4.

### 7.4 Mithin session 2 (the "timestamp screenshots")
- There were **no image screenshots**. The material is a **13.6 s phone screen-recording** of a stopwatch's lap list. We decoded it (OpenCV) and transcribed 17 laps: **lap 1 = 18:00.84, then alternating ~90 s and ~30 s laps, then 3.96 s; total 33:34.04** (sum of laps differs by 0.08 s).
- **Directly observed:** lap times. **Calculated:** cumulative boundaries. **Inferred (not in the video):** that the seven ~30 s laps are the holds.
- This is the **session-1-style schedule** (7 holds), not the newer protocol v2 (9 holds, sync taps).
- **Synchronisation test:** the stopwatch shares no event with any sensor tile, so we scanned every possible offset and asked "does the accelerometer's breathing amplitude drop at the inferred hold times?", comparing against 300 shuffled copies. **No tile beats chance** (p = 0.90 ECG, 0.95 EMG, 0.49 EOG). So session 2 gives **no labelled events**. A parallel run's different scan reported p = 0.04 for two tiles, but that used a weaker design (only 2 holds overlapping, uncorrected for 3 tiles, unequal offset grids), so we do not accept it.
- Also: the three tiles have different durations and independent clocks; all end with one truncated row; one Drive copy of the EOG file is cut off.
- **Consequence:** session-2 intervals are written in the annotation file but marked `uncertain`, `unaligned`, and excluded from training.
- **What would fix it:** re-record with sync taps and film the stopwatch next to the box once.

### 7.5 Ensembles (Track A, saved predictions)
`results/ensemble/`. Methods: majority vote, soft averaging, weighted averaging, calibrated averaging, stacking; combinations such as CNN+TCN+HGB.
- **No ensemble beats the single HGB.** Example: pre-chosen ensemble CNN+TCN+HGB: accuracy +0.000 [−0.016, 0.015], AUROC +0.005 [−0.012, 0.022] vs HGB. The best-looking ensemble (+0.005 accuracy, +0.011 AUROC) comes from picking the best of 40, so it's optimistic.
- Per record: improves 13, worsens 8 of 35 — not consistent.
- GRU and LSTM add nothing (their mistakes largely overlap with the others').
- Costs: CNN 2.7 ms, TCN 23.5 ms, HGB 9 ms per 1000 windows on one CPU thread; an ensemble costs the sum.
- **MESA ensembles:** without SpO2 none beats CANet (stacking ≈ equal, simple average slightly worse). With SpO2 the best ensemble gains +0.006 AUROC — statistically positive, practically negligible, and SpO2 isn't on our hardware.
- **Caveat we state openly:** second-level fitting uses out-of-fold predictions; a training record's prediction came from a model that had seen the test record, a weak indirect leak that is not removable without a huge nested rerun.
- **Recommendation: keep the single HGB. No ensemble.**

### 7.6 Synthetic data (simulator) — what we built
(`docs/SYNTHETIC_DATA.md`, `src/synth/`)
1. **Measured specification** from our recordings: sampling rate and timestamp step, HR range (48–79 bpm), noise levels, breathing rates, file format (16 columns), accelerometer unit conversion, and — found late — that **every real QVAR value is a multiple of 4**. Things not measurable are listed as **assumptions**.
2. **Simulator:** beat-by-beat heart model (breathing-driven variability, optional apnea-style slow-down/speed-up), ECG waveform built from real measured beat shapes with noise/baseline wander, accelerometer with gravity + breathing + noise + motion bursts, optional sync taps. Ground-truth event times come from the schedule, not from the signal. Deterministic for a given seed.
3. **Datasets** (not in git, regenerate with `python -m src.synth.gen`): **pilot 20 recordings, medium 100 (50 h), large 400 (200 h)**. Valid under the required checks: 20/20, 93/100, 377/400. Every recording has a manifest entry, marked "not a human recording".
4. **Automatic validator:** columns, timestamps, units, gravity, saturation, flat-lines, heart-rate plausibility, beat count vs truth, QVAR quantisation…
5. **Quality control:** the simulated data are **not** realistic enough to pass as real: a classifier separates real from synthetic windows with **AUROC 0.95** (it was 0.9997 until we added the 4-unit quantisation). The main remaining giveaway is the accelerometer breathing amplitude. Some features fall inside the real range for most recordings (QVAR spread 70%, wander 91%, breathing amplitude 100%), but QRS width is too wide. No near-duplicate recordings were found.
6. **Where the generator did use real data:** its parameter ranges came from our recordings. For the in-house breath-hold experiments, the generator was re-fitted **without session 1** so it can't leak into the test.

### 7.7 Augmentation
ECG sequences: gain, R-peak jitter, amplitude noise, small shift, time-warp, slow drift, premature beat, dropout (sets "A: conservative" and "B: channel-specific", plus each alone). Breath-hold windows: gain, small joint rotation, noise, drift, time-warp, band-edge change. **Applied only to training data.**

### 7.9 The breath-hold track (Track B) — the in-house work
(`results/inhouse_bh/README.md`)

**Task:** from the chest accelerometer, decide for each 10-second window whether it looks like a **voluntary breath-hold** versus normal breathing or recovery.

**Labels** (`results/inhouse_bh/annotations.csv`): session 1 only. 7 hold cores (≈20 s each = 142 s total), 7 baseline stretches (375 s), 7 recovery stretches (140 s), and **14 "uncertain" bands of ±5 s around each hold boundary** (because the stopwatch lag is about 5 s and the earlier boundary detector failed on 4 of 7 events). Three holds were visually confirmed (`high` confidence), four are `medium`. Uncertain bands are never used for training.

**Data size:** 237 labelled windows (40 hold, 197 not hold). From session 1 only — one volunteer, 7 events.

**Evaluation:** **leave-one-event-out** (7 folds × 3 seeds): train on 6 events, test on the 7th. **This is not an independent-person test.** Threshold fixed at 0.5.

**What was tried and the results (pooled AUROC)**
| Configuration | AUROC | Events with ≥ half the hold flagged |
|---|---|---|
| Real only, LR / HGB / CNN | 0.805 / 0.769 / 0.777 | 5 / 4 / 5 of 7 |
| Real only, ensemble (average of the three) | **0.826** | 4 of 7 |
| + augmentation | 0.812 | 4 of 7 |
| + simulator windows | 0.792 | 5 of 7 (but 36% flagged in unlabelled time vs 13%) |
| Pre-train on simulator, fine-tune | 0.807 | 4 of 7 |
| **SSL pre-training** on other in-house recordings + linear head | **0.828** (AP 0.648) | 5 of 7 |
| SSL pre-training, then fine-tune | 0.811 | 4 of 7 |

**Reading it:**
- Everything lands around AUROC 0.77–0.83; with only 7 events, the differences between settings are **within noise**.
- Augmentation doesn't help. Simulator windows raise sensitivity but cause many more false flags.
- SSL + linear head looks best but is a **hypothesis**, not a result, at this sample size.
- **Events 3 and 5 are almost never detected** — the same two events that earlier looked wrong by eye (a burst in the middle; not a clean quiet stretch).

**Whole-recording check** (what a demo actually shows): scoring *every* window of session 1, the real-only ensemble at threshold 0.5 and ≥ 18 s segments found **4 of 7 holds with 6 extra segments (≈ 12 per hour)**. Adding augmentation + simulator found 5/7 but **22 extra segments (≈ 44 per hour)**. So the model we deploy is the **real-only ensemble**. The extra flags are mostly "valleys" where breathing is quiet.
(Note: this threshold sweep reuses the 7 events, so it is optimistic. We did **not** pick the deployed threshold from it; the 0.5 and 18 s values were fixed beforehand.)

**Healthy overnight recordings as controls** (not used for training): 10 recordings, 0–0.9% of windows flagged, 0–1.2 flagged segments per hour. But for five of them most windows were rejected as "flat sensor" — the accelerometer's breathing band was at the sensor's noise floor, i.e. the box was not on a breathing chest. So these are **not** a specificity estimate.

## 8. The big-picture findings, ranked

1. **Best ECG-only model:** gradient boosting on HRV/CVHR features (0.802 / 0.839).
2. **Fusing effort helps on public data** (MESA 0.780 vs 0.609), but our accelerometer isn't a belt, so it doesn't transfer directly.
3. **More models (ensembles) and more data (augmentation, simulator) didn't help** at this data size, with proper confidence intervals.
4. **Breath-hold detection on our hardware is feasible but weak and fragile:** AUROC ≈ 0.8, catches 4/7 holds, many false alarms in quiet periods, one volunteer.
5. **Session 2 cannot be used for labels** (no alignment).
6. **The bottleneck is independent labelled data** (several people, with sync).

## 9. What is solid vs what is not

**Solid (reproducible, checked):** baseline numbers (recomputed); ensembles' null result; the checkpoint-path root cause and fix; the policy text; the session-2 alignment failure; the tests that ran.
**Moderately solid:** the expanded-data null result (3 seeds, real held-out records; wide CIs, so "no evidence of benefit", not "proof of no benefit"); the QC of the simulator (AUROC 0.95).
**Fragile / exploratory:** every breath-hold number (7 events, one volunteer, label boundaries uncertain by ±5 s); the SSL advantage; the "4/7, ~12 extra/hour" figure; healthy-control flag rates.
**Not done:** a validated breath-hold detector on independent people; fusion and per-night reports on our hardware; a quantitative stress test of the effort detector on simulated data; a signal-quality model; automated real-browser upload testing.

## 10. Limitations you should say out loud

- Healthy 19–20-year-olds only; **no clinical apnea accuracy on our hardware** and none claimed.
- Voluntary breath-holds are **not** clinical apnea.

## 14. Likely questions, with straight answers

**Q: What is the best model you have?**
A: For ECG-only apnea detection, gradient boosting on HRV/CVHR features: 80% per-minute accuracy, AUROC 0.84, tested on people it never saw. The 81% CNN number is an older single run that was chosen on the test data, so we don't headline it.

**Q: Did ensembles help?**
A: No. Every comparison's confidence interval includes zero; the apparent gains are from picking the best of many, or just averaging seeds.

**Q: Did synthetic data / augmentation help?**
A: No. Augmentation is neutral (best +1 point, not significant). Simulator data made it worse as we added more. We report that rather than hiding it.

**Q: Why not just train on our own data now that it's allowed?**
A: We did, for the breath-hold task. For the apnea task we can't — our volunteers have no apnea, so there are no clinical labels. And with only one volunteer and 7 events, a model trained on them can't be independently tested.

**Q: Is the breath-hold detector an apnea detector?**
A: No. It detects low chest-motion periods resembling voluntary holds. A hold is voluntary; apnea is a clinical event. We never relabel one as the other.

**Q: How good is the breath-hold detector?**
A: Moderate and fragile: AUROC about 0.8 in leave-one-event-out, finds 4 of 7 holds in a whole-recording scan with about 12 false segments per hour, one volunteer. It is a feasibility result.

**Q: Why couldn't you use the second session?**
A: Its "timestamps" are a stopwatch video, and the stopwatch shares no event with any sensor file. We tested all possible alignments against shuffled data and none beat chance, so we can't place the holds in the signal. It needs sync taps and a filmed stopwatch next time.

**Q: What was the dashboard bug?**
A: The model file was looked up using the folder you launched from, and that file's folder is gitignored, so fresh clones lacked it. Now paths come from the project root, the file's hash is checked, and a missing/wrong file gives a clear message. It never swaps in a different model.

**Q: What does the dashboard do when nothing is flagged?**
A: It says no breath-hold-like segments were flagged by this model in this recording — and that this doesn't mean breathing was normal or that apnea is absent.

**Q: Why does the synthetic upload show nothing?**
A: The detector learned real signals; the simulator is distinguishable from real data (AUROC 0.95). Synthetic files are for testing the pipeline, not for showing detection.

**Q: What's the main risk in what you present?**
A: Over-reading the breath-hold results. Seven events from one volunteer cannot support claims about new people.

**Q: What should we do next?**
A: Record **3 or more** volunteers with the v2 protocol (sync taps, filmed stopwatch, laps file, same box placement), with ECG and IMU on the same box. That would allow a genuine independent test and probably matters more than any further modelling.

**Q: What would the next modelling step be if more data arrive?**
A: Retest SSL pre-training + a linear head for breath-holds; try a context-aware detector; revisit fine-tuning the effort encoder.
